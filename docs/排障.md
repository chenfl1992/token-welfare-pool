# 排障手册

先跑一次健康检查，它会直接告诉你哪一项没通过以及对应建议：

```bash
node bootstrap/doctor.mjs
node bootstrap/control.mjs status
```

日志：`config/generated/freellmapi.log`、`ofm.log`、`tunnel.log`。

## 高频问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 客户端报 `4100 no endpoint url configured` | 旧会话持有启动时的模型配置快照 | **新开一个对话**，不用改配置 |
| 模型列表是空的 | 新库没有任何渠道 | 管理页添加 DSH 渠道并同步模型，再跑 `seed-group.mjs` |
| `my-group` 调用失败但其他模型正常 | 组内成员全被限流，或没有视觉成员却发了图片 | 等冷却恢复；`node bootstrap/seed-group.mjs` 重建分组 |
| 网关报「数据目录已被服务占用」 | 异常退出残留 `service.lock` | 确认端口上没有旧进程后，删除 `ofm-data/service.lock` 再启动 |
| 签到启动后没跑 | 网关还没起来，或当天已签过 | 等启动后 30 秒的补签；失败则每 6 小时重试 |
| 某模型偶发 `ECONNRESET` | 上游渠道瞬时抖动 | 路由会自动绕开，通常无需处理 |
| 公网隧道请求 404 | 旧 `~/.cloudflared/config.yml` 干扰 | 用 `--config` 显式指向自己的配置文件 |
| 重启后服务没起来 / 丢模型 | 运行目录放在 `/tmp` 被系统清空 | 迁到家目录下的固定位置，重新注册自启 |
| 测试公网地址返回空 | 本机代理环境变量干扰 | `curl --noproxy '*' https://你的域名/v1/models` |
| `npm ci` 报 EIO 或包损坏 | 安装路径权限/网络问题 | 换到普通家目录安装；必要时删 `node_modules` 和 `package-lock.json` 重装 |
| 所有渠道报无法解密密钥 | 数据库和 `.encryption-key` 不是一对 | 恢复与数据库配套的密钥文件，或重新添加渠道 |
| launchctl 报 I/O error | 沙箱或当前会话限制 | plist 已就位，重新登录后由 launchd 自动加载 |

## 诊断顺序

1. **Node 版本**：`node -v`，需 22.19+ 或 24.x。
2. **端口**：`node bootstrap/control.mjs status`，看 3001 / 18899 是否在监听。
3. **编译产物**：`apps/freellmapi/server/dist/index.js` 是否存在；没有就 `npm run build:server`。
4. **数据库**：`apps/freellmapi/server/data/freeapi.db` 是否存在；首次启动应自动创建。
5. **渠道**：管理页里渠道是否 `enabled`、health 是否正常。
6. **模型**：`GET /v1/models` 带统一密钥，看是否有模型。
7. **分组**：`node bootstrap/seed-group.mjs` 后看 `my-group` 是否与预期成员一致。
8. **公网**：本机通了再查隧道；公网 404 先怀疑旧 cloudflared 配置。

## 收集报告

求助时请附上：

- `node -v`、`node bootstrap/control.mjs status` 输出
- `node bootstrap/doctor.mjs` 输出
- `config/generated/freellmapi.log` 最后 50 行

**不要把密钥、数据库、`.env`、`config/deployment.json` 或 cloudflared 凭据贴出去。**
