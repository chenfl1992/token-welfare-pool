# 接入客户端

## 三个参数走天下

freellmapi 是标准 OpenAI 兼容接口，任何支持「自定义模型 / 自定义端点」的智能体都能接：

| 参数 | 填写内容 |
|---|---|
| Base URL / 接口地址 | `http://127.0.0.1:3001/v1`（本机）；局域网或公网时用对应地址 |
| API Key / 密钥 | 管理页里的统一密钥，形如 `freellmapi-xxxx` |
| Model / 模型名 | `my-group`（推荐）、`auto` 或 `/v1/models` 里的具体 id |

统一密钥在管理页可查看/重置；也可以执行 `node bootstrap/doctor.mjs`，健康检查通过时说明密钥可用。

## WorkBuddy

编辑 `~/.workbuddy/models.json`，追加一条：

```json
{
  "id": "my-group",
  "name": "my-group",
  "vendor": "Custom",
  "url": "http://127.0.0.1:3001/v1/",
  "apiKey": "freellmapi-<你的统一密钥>",
  "supportsToolCall": true,
  "supportsImages": true,
  "supportsReasoning": false,
  "useCustomProtocol": false
}
```

`supportsImages` 必须为 `true`，否则带图片的会话会在客户端侧被拦掉，走不到视觉分流逻辑。

> 🚨 **最坑的一个坑**：报 `Custom model custom-local:my-group has no endpoint url configured (4100)`，但配置里明明写了 url。原因是**旧会话持有启动时的模型配置快照**，那会儿还没有 my-group。解决：新开一个对话，不用改任何配置。

## 其他客户端

| 客户端 | 能否接入 | 说明 |
|---|---|---|
| WorkBuddy | ✅ 已验证 | `models.json` 加一条，见上 |
| Codex CLI | ✅ 可接入 | 在配置里添加 OpenAI 兼容自定义 provider，Base URL 填 `/v1` 地址 |
| Gemini CLI 等 | ✅ 可接入 | 只要支持 OpenAI 兼容 endpoint 即可 |
| 任意自研智能体 | ✅ 可接入 | 直接调用 `/v1/chat/completions` |
| 官方 ChatGPT.app | ❌ 不行 | 官方客户端不支持自定义 endpoint |
| Claude Code | ⚠️ 需转接 | 使用 Anthropic 协议，需额外转换层 |

最小调用示例：

```bash
curl http://127.0.0.1:3001/v1/chat/completions \
  -H "Authorization: Bearer freellmapi-<你的统一密钥>" \
  -H "Content-Type: application/json" \
  -d '{"model":"my-group","messages":[{"role":"user","content":"只回复 OK"}]}'
```

## 兼容性实测

- 模型列表自动发现 ✅
- 普通对话与流式输出 ✅
- 工具调用（function calling）✅ 连续多轮正确触发

## 多智能体共享

同一份地址可以给多台电脑的多个智能体共用：

1. 仅局域网：把 `host` 配成 `0.0.0.0`，其他电脑填 `http://<内网IP>:3001/v1`。
2. 异地访问：用 Cloudflare 隧道，见 [公网与自启](公网与自启.md)。
3. SSH 端口转发（临时）：`ssh -L 3001:127.0.0.1:3001 user@host`，本机继续用 `127.0.0.1:3001`。

共享时注意密钥保管：拿到「地址 + Key」的人都能调用你的额度。
