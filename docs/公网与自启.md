# 公网与自启

## 局域网共享

在配置向导里把监听地址设为 `0.0.0.0`：

```bash
node bootstrap/setup.mjs      # 监听地址填 0.0.0.0，其他项按需
node bootstrap/control.mjs stop
node bootstrap/control.mjs start
```

查本机内网 IP：

```bash
ipconfig getifaddr en0        # macOS
hostname -I                   # Linux
```

其他电脑填 `http://<内网IP>:3001/v1`。注意防火墙放行 3001；内网 IP 会随 DHCP 变化，建议在路由器里绑定固定 IP。

## 公网固定地址（Cloudflare 隧道）

不需要公网 IP，不用做端口映射，还自带 HTTPS。

### quick 模式（临时地址）

```bash
cloudflared tunnel --url http://127.0.0.1:3001
```

会打印一个 `https://xxx.trycloudflare.com` 地址，重启后变化。适合先验证公网链路。配置向导里 `tunnelMode` 选 `quick` 可将启动交给安装脚本托管。

### named 模式（固定域名）

前提：有一个把 NS 托管到 Cloudflare 的域名。

```bash
# 1. 创建隧道，记下返回的 UUID
cloudflared tunnel create tokenpool-tunnel

# 2. 绑定域名（自动添加 CNAME 记录）
cloudflared tunnel route dns tokenpool-tunnel your.domain.com
```

写配置文件（例如 `config/tunnel.yml`）：

```yaml
tunnel: <你的隧道UUID>
credentials-file: <你的UUID>.json
ingress:
  - hostname: your.domain.com
    service: http://127.0.0.1:3001
  - service: http_status:404
```

配置向导里 `tunnelMode` 选 `named`，填入隧道名和配置文件**绝对路径**，然后把公网地址写回 `config/deployment.json` 的 `publicUrl`，便于健康检查：

```json
"publicUrl": "https://your.domain.com/v1"
```

> ⚠️ **隧道连上了但公网 404**：多半是 `~/.cloudflared/config.yml` 里的旧配置在干扰。用 `--config` 显式指向新配置文件即可绕开（安装脚本已经这么做了）。

> 🔒 **安全**：公网暴露 + 固定 Key，任何拿到「地址 + Key」的人都能调用。建议用足够强的随机 Key，或在 Cloudflare Access 里加访问控制。

## 开机自启

安装脚本会按平台自动注册，无需手写配置：

| 平台 | 注册位置 | 服务名 |
|---|---|---|
| macOS | `~/Library/LaunchAgents/com.tokenpool.*.plist` | `com.tokenpool.freellmapi` / `.ofm` / `.tunnel` |
| Linux | `~/.config/systemd/user/tokenpool-*.service` | `tokenpool-freellmapi` / `tokenpool-ofm` |
| Windows | 任务计划程序（登录时触发） | `TokenPool-freellmapi` / `TokenPool-ofm` |

这些文件由 `node bootstrap/control.mjs install-autostart` 根据 `config/deployment.json` 生成，**包含本机 node 绝对路径和仓库路径**，不可跨机器复制。换电脑后重新运行安装脚本即可。

常用：

```bash
node bootstrap/control.mjs install-autostart     # 重新注册
node bootstrap/control.mjs uninstall-autostart   # 移除
node bootstrap/control.mjs status                # 查看状态
```

macOS 上有时会遇到 `launchctl bootstrap` 报 I/O error（沙箱或会话限制）；plist 已经就位，重新登录后 launchd 会自动加载。

## 数据持久化

> 🚨 **绝对不要把运行目录放在 `/tmp` 下。** macOS 重启会清空 `/tmp`，数据库（渠道密钥、模型配置全在里面）和 `.encryption-key` 会一起丢失，开机自启也会失败。请始终放在家目录或固定的工作目录下。

需要备份或迁移时：

1. 先 `node bootstrap/control.mjs stop` 停服，保证 WAL 数据落盘。
2. 成对备份 `apps/freellmapi/server/data/freeapi.db` 和同目录的 `.encryption-key`，以及 `ofm-data/`。
3. 迁移后在新位置重新运行 `setup.mjs` 和 `install-autostart`，修正路径。
4. 只备份数据库、不备份密钥文件，恢复后所有渠道密钥都无法解密（日志会报 `Unsupported state or unable to authenticate data`）。

日志位置：

- `config/generated/freellmapi.log`
- `config/generated/ofm.log`
- `config/generated/tunnel.log`

排障时先看这三个文件。
