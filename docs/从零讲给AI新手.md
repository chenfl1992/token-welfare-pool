## 01 | 为什么要自己搭一个模型池

如果你也在为这几件事头疼，这篇教程就是为你写的：

- 💸 **官方 API 太贵**：高频用户一个月动辄几百上千，token 烧得像流水。
- 🚫 **免费额度总被限流**：好不容易找到免费渠道，用一会儿就 429，体验极差。
- 🎲 **模型质量参差不齐**：同一个请求，这次秒回，下次超时，还经常遇到根本调不通的"僵尸模型"。
- 🧧 **签到领额度太麻烦**：十几个平台，每天手动点签到，谁有那功夫？

市面上的免费模型聚合项目不少，但大多只解决了"把模型列出来"这一步。真正难的是三件事：**让额度持续续上、让限流自动绕开、让调用又快又稳。**

这套方案要做的，就是把这三件难事一次性打包解决——你只管在客户端里填一个地址，剩下的它自己搞定。

> 💡 **羊毛哥的态度**：薅羊毛不是抠门，是把资源用到极致。免费的东西如果能做到稳定可用，那就是真香。

## 04 | 三步搭好核心链路

### 步骤 1：准备环境

需要 Node.js 22.19+ 或 24.x。然后把项目 clone 到**固定的家目录位置**（千万不要放 `/tmp`，重启会清空）：

```bash
git clone <你的仓库地址> token-welfare-pool
cd token-welfare-pool
```

### 步骤 2：一键安装

```bash
./install.sh --defaults      # macOS / Linux
```

Windows 用：

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -Defaults
```

一条命令搞定：检查 Node → 装依赖 → 编译 → 生成配置 → 注册开机自启 → 启动服务 → 健康检查。

### 步骤 3：添加渠道，创建单入口

1. OFM 网关启动日志里会打印「管理页面（10 分钟内一次性登录）」，打开它登录。
2. 在 freellmapi 管理页 `http://127.0.0.1:3001` 注册管理员，添加一条 DSH 渠道：Base URL 填 `http://127.0.0.1:18899/v1`，密钥填 OFM 的转发密钥。
3. 等模型同步完成，然后：

```bash
node bootstrap/seed-group.mjs
node bootstrap/doctor.mjs
```

看到 `my-group 实际调用 ✓`，核心链路就通了。

> ✅ **关键指标**：渠道 `enabled=1`、health 正常、模型列表非空、`my-group` 能实际返回内容。

## 05 | 自动签到：让额度自己续上

签到服务会遍历所有已配置的 DSH 渠道，通过网关管理接口调用 `credits.claimAll` 逐个领取每日额度。成功后还会做两件聪明事：**清除该渠道昨天的限流冷却**（领了新额度就该重新能用），以及**顺手同步一次模型列表**。

### 什么时候会自动签到

- **服务启动后 30 秒** —— 补签一次，保证白天开服也能领到
- **每天 00:05（本地时间）** —— 主签到点，额度午夜重置后立刻领取
- **每 6 小时一次机会** —— 当天 00:05 那次若失败，后续自动补签；靠「当天去重」保证实际每天只签一次

> ℹ️ **幂等设计**：网关对已签到的渠道会去重，重复签到不会重复发额度也不会报错。放心让服务频繁尝试——它自己知道该不该签。

## 06 | 智能分组与模型排名

这是整套方案的灵魂：不是「能用就行」，而是「自动选最好的那个」。

### 排名优先级

1. **不限流** —— 没有 429、不在冷却中的模型永远排最前
2. **响应快** —— 同样可用时，延迟低的优先
3. **更智能** —— 能力强的模型获得更高权重

实现上，路由层把模型分成「无约束组」和「受限组」：没有限流、没有冷却的模型整体排在受限组前面；只有当前置条件相同时，才用响应速度和智能度做二次排序。

> 💡 **一个关键修正**：本地网关是聚合网关，某一个渠道返回 5xx 并不代表整个网关挂了。所以特意让 dsh 平台豁免「平台级错误整体跳过」的逻辑——否则一次渠道抖动会导致所有模型被误判不可用。

### 精选模型分组：my-group

自动路由虽兜底能力强，但它在数百个模型里挑，偶尔会撞上慢渠道。于是我们建了一个只包含实测稳定、快速模型的分组 `my-group`。使用时客户端填的模型名就是 `my-group`。

更进一步，`my-group` 是**文本 + 视觉二合一**的单入口：

- 纯文字请求 → 自动走最快的文本模型
- 带图片请求 → 自动走视觉模型；组内没有视觉成员时剥掉图片转文字兜底，不再报错

这样客户端只需要维护一个模型名，不用分别配 `my-group` 和 `my-vision`。

## 07 | 接入你的 AI 客户端

标准 OpenAI 兼容接口，三个参数：

| 参数 | 填什么 |
|---|---|
| Base URL / 接口地址 | `http://127.0.0.1:3001/v1`（本机）或公网域名 |
| API Key / 密钥 | 管理页的统一密钥 `freellmapi-...` |
| Model / 模型名 | `my-group`（推荐）或 `auto` / 其他具体模型 |

以 WorkBuddy 为例，编辑 `~/.workbuddy/models.json`，追加一条：

```json
{
  "id": "my-group",
  "name": "my-group",
  "vendor": "Custom",
  "url": "http://127.0.0.1:3001/v1/",
  "apiKey": "freellmapi-<你的统一密钥>",
  "supportsToolCall": true,
  "supportsImages": true
}
```

> 🚨 **最坑的一个坑**：报错 `Custom model custom-local:my-group has no endpoint url configured (4100)`。配置明明写了 url，却报没有 url？这是因为**旧会话**启动时把模型配置存了快照，那时 my-group 还不在配置里。解决办法极其简单——**新开一个对话**就好。

实测兼容性：模型列表自动发现 ✅、普通对话 ✅、流式输出 ✅、工具调用 ✅（连续多轮正确触发）、带图片对话 ✅。

## 08 | 实测：精选分组 vs 全自动路由

用同一句「只回复两个字：正常」，各跑 5 轮（历史实测数据，具体数值随渠道波动）：

| 轮次 | my-group | auto |
|---|---|---|
| 1 | 2.0s | 16.8s |
| 2 | 1.8s | 4.6s |
| 3 | 1.0s | 20.1s |
| 4 | 1.9s | 33.5s |
| 5 | 0.9s | 9.5s |
| **平均** | **≈1.5s** | **≈16.9s** |

> 🎯 **结论**：my-group 平均快约 **11 倍**，且极其稳定。原因是它只在精挑细选的模型里路由，基本一击命中；而 auto 在大池子里挑，会撞到慢渠道、额度耗尽、429 限流，然后不断重试降级。**日常用 my-group，兜底场景才用 auto。**

## 09 | 进阶玩法：从本机到全世界

### 9.1 接入其他智能体

| 客户端 | 能否接入 | 说明 |
|---|---|---|
| WorkBuddy | ✅ 已验证 | models.json 加一条即可 |
| Codex CLI | ✅ 可接入 | 配 OpenAI 兼容自定义 provider |
| Gemini CLI 等 | ✅ 可接入 | 支持 OpenAI 兼容 endpoint 即可 |
| 官方 ChatGPT.app | ❌ 不行 | 官方客户端不支持自定义 endpoint |
| Claude Code | ⚠️ 需转接 | 用 Anthropic 协议，要加一层转换 |

### 9.2 局域网共享

配置向导里把监听地址设为 `0.0.0.0`，其他电脑填 `http://<内网IP>:3001/v1`。注意防火墙别拦，内网 IP 可能因 DHCP 变化，建议路由器里绑定固定 IP。

### 9.3 公网固定地址（异地也能用）

用 **Cloudflare 命名隧道**——不需要公网 IP、不用做端口映射，还能白嫖 HTTPS。前提：有一个把 NS 托管到 Cloudflare 的域名。

```bash
cloudflared tunnel create tokenpool-tunnel
cloudflared tunnel route dns tokenpool-tunnel your.domain.com
cloudflared tunnel --config config/tunnel.yml run tokenpool-tunnel
```

在配置向导里选 `named` 模式，填隧道名和配置文件绝对路径，安装脚本会自动注册隧道的开机自启。

> ⚠️ **隧道连上了但公网 404？** 大概率是 `~/.cloudflared/config.yml` 里有旧的无效配置在干扰。用 `--config` 显式指向新配置文件即可绕开。

> 🔒 **安全提醒**：公网暴露 + 固定密钥，任何拿到「地址 + key」的人都能调用。要么加 Cloudflare Access，要么把密钥换成足够强的随机串。

### 9.4 开机自启 + 数据持久化

安装脚本已经按平台注册好：macOS 用 launchd，Linux 用 systemd user，Windows 用任务计划程序。`RunAtLoad` + `KeepAlive` 保证开机启动、崩溃重启。

> 🚨 **必须做的数据迁移！** 千万别把项目放在 `/tmp` 下——macOS 重启会清空 `/tmp`，数据库（密钥、模型配置全在里面）会丢。请放在家目录或固定工作目录。迁移时先停服、再同步、最后重启，保证 WAL 数据一致。

```bash
node bootstrap/control.mjs stop        # 迁移前停服
node bootstrap/control.mjs status      # 重启后验证
```

## 10 | 踩坑指南与福利总结

| 现象 | 原因 | 解决 |
|---|---|---|
| 客户端报 4100「no endpoint url」 | 旧会话的模型配置快照没更新 | 新开对话 |
| 网关「数据目录已被占用」 | 异常退出残留死锁 | 确认无进程后删 `service.lock` |
| 签到启动后没跑 | 网关还没起来 / 当天已签过 | 等 30s 补签或看 6h 重试 |
| 某模型偶发 ECONNRESET | 上游渠道瞬时抖动 | 路由自动绕开，无需处理 |
| 公网隧道请求 404 | 旧 config.yml 干扰 | `--config` 显式指定新配置 |
| 重启后服务没起来/丢模型 | 放在 /tmp 被清空 | 迁到固定目录 |
| 测试公网地址返回空 | 本机代理环境变量干扰 | curl 加 `--noproxy '*'` |
